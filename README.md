# LLM Engineering – Insurellm RAG Assistant

A Retrieval-Augmented Generation (RAG) assistant that answers questions about the fictional company **Insurellm**.

It works in two stages:

1. **Ingestion** (`ingest.py`) reads the markdown files in the knowledge base, splits them into chunks, turns each chunk into an embedding vector, and stores everything in a local Chroma vector database.
2. **Chat app** (`app.py`) is a Gradio web UI. For each question it retrieves the most relevant chunks from the vector database and sends them, with the question, to an LLM to produce an answer. The retrieved context is shown beside the chat.

## Prerequisites

- **macOS, Linux or Windows** with a terminal
- **[uv](https://docs.astral.sh/uv/)** (Python package and environment manager)
- **Python 3.12** (uv can install it for you)
- **An OpenAI API key** (used by the chat model in `answer.py`)
- An internet connection for the first run. The embedding model (`all-MiniLM-L6-v2`) is downloaded from Hugging Face the first time and cached after that.

Install uv if you don't have it:

```bash
# macOS / Linux
curl -LsSf https://astral.sh/uv/install.sh | sh

# or with Homebrew
brew install uv
```

## Setup

### 1. Go to the project root

```bash
cd path/to/llm_engineering
```

All commands in this README are run from this folder.

### 2. Make sure Python 3.12 is used

```bash
uv python install 3.12
uv python pin 3.12
```

`pyproject.toml` must allow Python 3.12. Check it contains:

```toml
requires-python = ">=3.12"
```

If it says `>=3.14`, change it to `>=3.12`. Some AI libraries (such as PyTorch, which `sentence-transformers` depends on) may not yet have working builds for very new Python versions.

### 3. Install dependencies

```bash
uv sync
```

This creates `.venv/` and installs everything listed in `pyproject.toml`. If any package is missing, add it. For example:

```bash
uv add sentence-transformers
```

The libraries this project relies on include:

| Package | Purpose |
|---|---|
| `langchain-core`, `langchain-openai` | LLM wrapper and message types |
| `langchain-chroma`, `chromadb` | Vector database |
| `langchain-huggingface`, `sentence-transformers` | Local embedding model |
| `langchain-text-splitters`, `langchain-community` | Splitting and loading documents |
| `gradio` | Web UI |
| `python-dotenv` | Loads variables from `.env` |

### 4. Add your API key

Create a file named `.env` in the project root:

```bash
OPENAI_API_KEY=sk-your-key-here
```

Optional, to avoid Hugging Face rate-limit warnings when downloading the embedding model:

```bash
HF_TOKEN=hf_your-token-here
```

Never commit `.env` to git. Make sure `.gitignore` contains it:

```
.env
.venv/
data/vector_db/
__pycache__/
```

You can also keep a `.env.example` in the repo with variable names only:

```
OPENAI_API_KEY=
HF_TOKEN=
```

## Configuration

Shared settings live in `src/llm_engineering/config.py`. Both `ingest.py` and `answer.py` import from it, so the paths and embedding model always match.

```python
from pathlib import Path

# config.py -> llm_engineering -> src -> project root
ROOT = Path(__file__).resolve().parents[2]

DATA_DIR = ROOT / "data"
KNOWLEDGE_BASE = DATA_DIR / "knowledge-base"
DB_NAME = str(DATA_DIR / "vector_db")

EMBEDDING_MODEL = "all-MiniLM-L6-v2"
```

**Important:** the embedding model used to build the database must be the same one used to query it. If they differ, you will see an error like `Collection expecting embedding with dimension of 1536, got 384`. If you change `EMBEDDING_MODEL`, delete the database and re-run ingestion (see [Rebuilding the database](#rebuilding-the-database)).

Other settings in the code:

| Setting | File | Meaning |
|---|---|---|
| `chunk_size=500`, `chunk_overlap=200` | `ingest.py` | How documents are split |
| `RETRIEVAL_K = 10` | `answer.py` | Number of chunks retrieved per question |
| `MODEL` | `answer.py` | The OpenAI chat model name. Set this to a model your account can access |

## Step 1 – Build the vector database (ingest.py)

Run this **once**, and again whenever the documents in `data/knowledge-base/` change.

```bash
uv run python -m llm_engineering.rag.ingest
```

### What it does

1. Looks inside each subfolder of `data/knowledge-base/` and loads every `.md` file.
2. Adds a `doc_type` metadata tag to each document (`company`, `contracts`, `employees` or `products`).
3. Splits documents into chunks of 500 characters with 200 characters of overlap.
4. Embeds every chunk with the `all-MiniLM-L6-v2` model (384-dimension vectors).
5. Saves the chunks and vectors in a Chroma database at `data/vector_db/`.

### Expected output

You should see something like:

```
There are 123 vectors with 384 dimensions in the vector store
Ingestion complete
```

(The exact vector count depends on your documents.) The key things to check are that the count is above zero and that the dimension is **384**.

Warnings about `langchain-community` being sunset, Pydantic V1 or unauthenticated Hugging Face requests can be ignored for now.

### Verify the database exists

```bash
ls data/vector_db
```

You should see a `chroma.sqlite3` file and one or more folders.

## Step 2 – Run the chat app (app.py)

After ingestion has finished:

```bash
uv run python -m llm_engineering.rag.app
```

Gradio will start a local server and open your browser, normally at <http://127.0.0.1:7860>. If the browser doesn't open, copy the URL from the terminal.

### Using the app

- Type a question in the **Your Question** box and press Enter, for example:
  - `Who is Avery?`
  - `What products does Insurellm offer?`
  - `Tell me about the contract with GreenField Holdings.`
- The conversation appears on the left.
- The retrieved context (the source chunks used for the answer) appears on the right, with the file each came from.

Conversation history is used when retrieving context, so follow-up questions work.

Stop the app with `Ctrl + C` in the terminal.

## How it works

```
data/knowledge-base/*.md
        │
        ▼  ingest.py
  load → split into chunks → embed (all-MiniLM-L6-v2) → store in Chroma
                                                          │
                                                   data/vector_db/
                                                          │
User question ──► app.py ──► answer.py                    │
                               │  combine prior user messages + new question
                               │  retrieve top-k similar chunks ◄─────────────┘
                               │  put chunks into the system prompt
                               ▼
                       OpenAI chat model ──► answer (+ context shown in the UI)
```

- `ingest.py` – `fetch_documents()`, `create_chunks()` and `create_embeddings()`.
- `answer.py` – `fetch_context()` retrieves chunks, `answer_question()` builds the prompt and calls the LLM.
- `app.py` – the Gradio interface, which calls `answer_question()` for each message.

## Rebuilding the database

Delete the old database and run ingestion again when you:

- change the documents in `data/knowledge-base/`
- change `EMBEDDING_MODEL`
- change chunk size or overlap

```bash
rm -rf data/vector_db
uv run python -m llm_engineering.rag.ingest
```

## Troubleshooting

### `ValueError: Expected Embeddings to be non-empty list or numpy array, got [] in upsert`

No documents were loaded, so there were no chunks to embed. Check:

- `data/knowledge-base/` exists and contains the subfolders with `.md` files.
- `KNOWLEDGE_BASE` in `config.py` points to the right place. `ROOT` should be the project root (the folder containing `pyproject.toml`).
- You are not accidentally using an old relative path in `ingest.py`.

Quick check:

```bash
find data/knowledge-base -type f | wc -l
```

### `InvalidArgumentError: Collection expecting embedding with dimension of 1536, got 384`

The database was built with a different embedding model (1536 dimensions is typical of OpenAI embeddings) than the one you are querying with (384 for `all-MiniLM-L6-v2`). Delete `data/vector_db` and re-run ingestion, and make sure both `ingest.py` and `answer.py` import `EMBEDDING_MODEL` from `config.py`.

### `ModuleNotFoundError: No module named 'sentence_transformers'`

```bash
uv add sentence-transformers
```

If installation fails on a very new Python version, switch to Python 3.12 as described in [Setup](#setup).

### `The requested Python version 3.12 is incompatible with the project requires-python value of >=3.14`

Edit `pyproject.toml` and set `requires-python = ">=3.12"`, then run `uv python pin 3.12`, remove `.venv` and run `uv sync`:

```bash
rm -rf .venv
uv sync
```

### `TypeError: Chatbot.__init__() got an unexpected keyword argument 'type'`

Gradio 6 removed the `type` argument from `gr.Chatbot` (messages format is now the default). Remove `type="messages"`. Also move `theme=` from `gr.Blocks(...)` to `ui.launch(...)`. If you get a similar error for `show_copy_button`, remove it too. Alternatively pin Gradio below version 6:

```bash
uv add "gradio<6"
```

### The app opens but answers are empty or say "I don't know"

- Check that `answer.py` uses `DB_NAME` from `config.py` (not a path built from `__file__`). A wrong path means the app reads an empty database.
- Check that `data/vector_db/` exists and was created by a successful ingestion.
- Look at the "Retrieved Context" panel. If it is empty, retrieval is failing. If it shows relevant text but the answer is wrong, the issue is in the model call.

### Model not found / unsupported parameter errors

The `MODEL` value in `answer.py` must be a model your OpenAI account can use. If the error mentions `reasoning_effort`, remove that argument from `ChatOpenAI(...)`, since not every model accepts it.

### `AuthenticationError` / missing API key

Check `.env` is in the project root and contains `OPENAI_API_KEY=...`, with no quotes or spaces around the `=`. Run from the project root so `load_dotenv` can find it.

### Warning: "You are sending unauthenticated requests to the HF Hub"

Harmless. Add `HF_TOKEN` to `.env` for higher rate limits.

### Imports fail with `ModuleNotFoundError: No module named 'llm_engineering'`

Run commands from the project root using `uv run python -m llm_engineering.rag.<module>`, not `python ingest.py` from inside the `rag` folder. Also confirm `__init__.py` exists in `src/llm_engineering/` and `src/llm_engineering/rag/`.

## Notes and tips

- Run everything from the project root so relative imports and `uv` pick up the right environment.
- Keep the `.env` file out of git, and rotate any API key that was ever committed.
- `data/vector_db/` is generated output. It doesn't need to be committed.
- The Chroma database is local. Deleting the `data/vector_db` folder resets it.
- To add new knowledge, put `.md` files into one of the subfolders of `data/knowledge-base/` (or add a new subfolder) and re-run ingestion.
